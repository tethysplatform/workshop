# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Docusaurus 3.10 static site that hosts the **Tethys Platform Workshop** — a guided tutorial series teaching users how to build apps and dashboards on the Tethys Platform (especially TethysDash with GEOGLOWS hydrologic data). The site is published to GitHub Pages at `https://tethysplatform.github.io/workshop/`.

Almost all editing is **content** (Markdown/MDX tutorials and images), not application code. The React/JS surface area is the default Docusaurus template, lightly themed.

## Commands

- `yarn` — install dependencies (Node >= 20 required)
- `yarn start` — dev server with hot reload (opens browser)
- `yarn build` — build static site to `/build`; **fails on broken links** (`onBrokenLinks: 'throw'`)
- `yarn clear` — clear the `.docusaurus` cache (use when stale build artifacts cause weird behavior)
- `yarn serve` — serve the built site locally
- `yarn deploy` — push to `gh-pages` branch (CI does this automatically; rarely needed locally)

CI: `.github/workflows/deploy.yml` runs `yarn build` and deploys to GitHub Pages on every push to `main`. Broken links/images will fail the deploy.

## Content architecture

All tutorial content lives directly under `docs/`. The sidebar is **auto-generated from the filesystem** (`sidebars.js` uses `{type: 'autogenerated', dirName: '.'}`), so:

- **`introduction.md`** is the first page (`sidebar_position: 0` ensures it precedes the numbered tutorials).
- **Numeric filename prefixes drive tutorial order** — `01-getting-started.md`, `02-component-applications.md`, etc. To insert or reorder tutorials, rename files; do not edit `sidebars.js`.
- **Subdirectories become sidebar categories.** The two TethysDash tutorials are grouped under `docs/03-tethysdash/` (with its own `01-creating-dashboards.md`, `02-creating-custom-plugins.mdx`, and a `_category_.json` defining the `TethysDash` label and default-expanded state). The directory's numeric prefix sets the category's position in the sidebar.
- Use `.md` for plain Markdown; use `.mdx` when a tutorial needs React components. The custom plugins tutorial (`03-tethysdash/02-creating-custom-plugins.mdx`) uses `Tabs`/`TabItem` from `@theme/Tabs` to present two alternative implementation paths (Grid Item vs. Popup Modal) for the same dashboard feature — see that file for the pattern.

## Asset layout (canonical)

This project follows Docusaurus's recommendation to **co-locate tutorial assets with the docs that reference them**. Two distinct roots:

- **`<tutorial-dir>/images/<tutorial-slug>/`** — tutorial screenshots, organized into one subfolder per tutorial, matching the tutorial's URL slug. The top-level tutorials reference them as `./images/<slug>/...` (e.g. `./images/getting-started/added-map-view.png`); the nested TethysDash tutorials reference them as `./images/creating-dashboards/...` and `./images/creating-custom-plugins/...` (within `docs/03-tethysdash/images/`). The TethysDash tutorials use a `<section>.<step>_description.png` filename convention (e.g. `2.6_plot_setup.png`); the getting-started tutorial uses kebab-case names. When adding a new tutorial, create a matching `images/<slug>/` subfolder alongside it.
- **Solution downloads alongside the tutorial that links to them** — currently `docs/03-tethysdash/GEOGLOWS_China_TethysDash.json`, `..._Part2.json`, `..._Part2_Popup_Modal.json`, referenced from the TethysDash tutorials with relative paths like `./GEOGLOWS_China_TethysDash.json`. Co-located so the download link travels with the tutorial. When updating a tutorial's steps, keep the matching solution JSON in sync.
- **`static/img/`** — **site-level assets only** (favicon, logos, social card, SVG illustrations used by React components in `src/`). Referenced from React/config with absolute paths like `/img/favicon.ico`. Do **not** put tutorial screenshots here.

## Site configuration

`docusaurus.config.js`:
- `baseUrl: '/workshop/'` — every absolute internal link must account for this. Prefer relative links and Docusaurus's `Link` component, which handle it automatically.
- `docs.routeBasePath: '/'` — the docs plugin serves at the site root, so tutorial URLs do **not** include a `/docs/` segment. Deployed URLs are `/<baseUrl>/<tutorial-slug>` (e.g. `/workshop/introduction`, `/workshop/getting-started`). The marketing landing page from `src/pages/index.js` still wins at `/<baseUrl>/`.
- `blog: false` — there is intentionally no blog plugin.
- `editUrl` currently points at the upstream Docusaurus template repo. If "Edit this page" links should point to the real workshop repo, update it to `https://github.com/tethysplatform/workshop/tree/main/`.

`src/pages/index.js` is a tiny redirect-only page: visiting the site root (`/workshop/`) sends users to `/workshop/introduction` via `<Redirect>`. There is no marketing landing page. If you want to restore one, replace the redirect with the usual hero/feature layout.

## Conventions for tutorial authoring

- Front matter is minimal — `title:` is the typical override; otherwise the first `#` heading becomes the title.
- Each tutorial starts with an **Objectives** section, then **Prerequisites**, then numbered **Steps**. Follow this shape when adding a new tutorial.
- External links to Tethys/TethysDash docs use the full `https://docs.tethysplatform.org/...` or `https://tethysdash.readthedocs.io/...` URLs. Internal cross-tutorial links use relative paths (e.g. `./03-tethysdash-creating-dashboards.md`).
- When introducing a TethysDash plugin attribute, prefer the existing table format (Attribute / Value / What it means) seen in `04-tethysdash-creating-custom-plugins.mdx`.

## Anti-patterns to avoid

- **Don't edit `sidebars.js` to add/reorder docs** — rename files instead. The current sidebar is fully auto-generated.
- **Don't add an absolute path that omits the `/workshop/` baseUrl** — it will 404 on the deployed site even though it works locally on `/`.
- **Don't introduce broken links or missing images** — the build will fail and the deploy will be blocked.
- **Don't move dashboard solution JSON files out of `docs/`** — their location alongside the tutorials is what makes them downloadable from the rendered tutorial pages.
