# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Docusaurus 3.10 static site that hosts the **Tethys Platform Workshop** — a guided tutorial series teaching users how to build apps and dashboards on the Tethys Platform (especially TethysDash with GEOGLOWS hydrologic data). The site is published to GitHub Pages at `https://tethysplatform.github.io/workshop/`.

Almost all editing is **content** (Markdown/MDX tutorials and images), not application code. The React/JS surface area is the default Docusaurus template, lightly themed.

## Commands

- `yarn` — install dependencies (Node >= 20 required)
- `yarn start` — dev server with hot reload (opens browser)
- `yarn build` — build static site to `/build`; **fails on broken links** (`onBrokenLinks: 'throw'`)
- `yarn clear` — clear the `.docusaurus` cache (use when stale build artifacts cause weird behavior)
- `yarn serve` — serve the built site locally
- `yarn deploy` — push to `gh-pages` branch (CI does this automatically; rarely needed locally)

CI: `.github/workflows/deploy.yml` runs `yarn build` and deploys to GitHub Pages on every push to `main`. Broken links/images will fail the deploy.

## Content architecture

All tutorial content lives under `docs/workshop/`. The sidebar is **auto-generated from the filesystem** (`sidebars.js` uses `{type: 'autogenerated', dirName: '.'}`), so:

- **Numeric filename prefixes drive order** — `01-getting-started.md`, `02-component-applications.md`, etc. To insert or reorder tutorials, rename files; do not edit `sidebars.js`.
- Use `.md` for plain Markdown; use `.mdx` when a tutorial needs React components. The TethysDash plugins tutorial (`04-...mdx`) uses `Tabs`/`TabItem` from `@theme/Tabs` to present two alternative implementation paths (Grid Item vs. Popup Modal) for the same dashboard feature — see that file for the pattern.
- `_category_.json` controls the category label and the auto-generated index page description.

Images live in `docs/images/` and are referenced from tutorials as `../images/filename.png`. Filenames follow a `<section>.<step>_description.png` convention (e.g. `2.6_plot_setup.png`).

**Dashboard JSON files in `docs/workshop/`** (e.g. `GEOGLOWS_China_TethysDash.json`, `..._Part2.json`, `..._Part2_Popup_Modal.json`) are **reference solutions** — exported TethysDash dashboards that workshop participants can import if they get stuck or want to skip ahead. They are not rendered by Docusaurus; they're served as static assets users download. When updating a tutorial's steps, keep the matching solution JSON in sync.

## Site configuration

`docusaurus.config.js`:
- `baseUrl: '/workshop/'` — every absolute internal link must account for this. Prefer relative links and Docusaurus's `Link` component, which handle it automatically.
- `blog: false` — there is intentionally no blog plugin.
- `editUrl` currently points at the upstream Docusaurus template repo. If "Edit this page" links should point to the real workshop repo, update it to `https://github.com/tethysplatform/workshop/tree/main/`.

`src/pages/index.js` is the marketing landing page; `src/components/HomepageFeatures/` are the feature tiles below the hero. These rarely change.

## Conventions for tutorial authoring

- Front matter is minimal — `title:` is the typical override; otherwise the first `#` heading becomes the title.
- Each tutorial starts with an **Objectives** section, then **Prerequisites**, then numbered **Steps**. Follow this shape when adding a new tutorial.
- External links to Tethys/TethysDash docs use the full `https://docs.tethysplatform.org/...` or `https://tethysdash.readthedocs.io/...` URLs. Internal cross-tutorial links use relative paths (e.g. `./03-tethysdash-creating-dashboards.md`).
- When introducing a TethysDash plugin attribute, prefer the existing table format (Attribute / Value / What it means) seen in `04-tethysdash-creating-custom-plugins.mdx`.

## Anti-patterns to avoid

- **Don't edit `sidebars.js` to add/reorder docs** — rename files instead. The current sidebar is fully auto-generated.
- **Don't add an absolute path that omits the `/workshop/` baseUrl** — it will 404 on the deployed site even though it works locally on `/`.
- **Don't introduce broken links or missing images** — the build will fail and the deploy will be blocked.
- **Don't move dashboard solution JSON files out of `docs/workshop/`** — their location is what makes them downloadable from the rendered tutorial pages.
